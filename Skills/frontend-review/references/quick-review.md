# 快速体检

目标是优先发现影响核心任务的问题，输出简短且可复核的部分审查。深度与授权规则见 SKILL 第 1 节；完整台账、逐实例蓝图与覆盖门槛不适用于本模式。

1. 记录项目位置、版本、访问能力、用户目标与已知限制，并说明本次是 quick、覆盖范围如何选定。
2. 看目录、路由与核心入口，列出已发现页面；从用户指定范围或主要用户旅程选定检查对象，写清选择理由与未查页面。发现脚本可选，其输出只是候选。
3. 检查所选旅程的成功、失败与恢复，以及直接相关的交互、状态、可访问性、数据与权限边界；按实际对象读取组件手册或专题参考。
4. 每项问题给定位、证据类型、复现条件或源码推理、实际与预期、影响、优先级、修复方向与复验方法；源码风险与运行复现分开写。
5. 先交付影响最大的发现，再给其余发现与未验证项。没有发现也说明实际检查了什么范围；"未发现"按字面意思是未发现。
6. 输出一份 quick-review.md：范围与基线、主要发现、修复顺序、未查与阻塞范围、下一步。证据按需单独保存。用户给了时间预算时，到点保留未查项并给出部分结论。

quick 交付依赖的是报告本身，不运行也不需要 `--require-plan`、`--require-complete`、`--require-ready`；已建台账时把 project.review_depth 写为 quick。

升级 full 时把发现与原始证据迁入稳定 ID 台账，逐项补齐页面、定义、实例、场景与方案；用户明确要求升级即继续执行，不再重复索取审查许可。
