# 逐组件生产重构方案

把审查证据转成可实施、可验收、可回滚的计划。实体、字段、处置词表与 target_contract 十维以台账协议为准；执行顺序见 SKILL 第 7–8 节，本文件只写方案写法。

## 1. 固定目标与实施边界

先明确产品阶段、可用输入、允许修改的范围、部署环境与必须保持的行为；未知前提显式列出，不依赖它们的检查与方案继续完成。

- 分别解释"当前缺陷""原型阶段省略的能力""新增产品需求"，让上线阻塞只落在真实缺陷与用户目标上。
- 沿用现有框架、组件库、数据层与设计系统；提出替换时写清具体限制、候选能力、迁移成本、依赖兼容与退出路径。
- 不可读的路由、账号角色、后端代码、生产流量与设备范围登记为覆盖限制。
- 尚未证实的高影响风险转成先行验证任务；根据猜测安排全系统重写会把不确定性放大成成本。
- 区分可交付的前端修复与端到端成立的产品结果：服务端缺少关键协议时，先安排接口依赖与诚实的前端过渡表现。

## 2. 处置选择

每个 CMP 一条 component_plan；同一 DEF 的不同实例允许不同处置。

| 处置 | 选择条件 | 交付要写清 |
|---|---|---|
| retain | 当前职责、行为与验证满足目标 | 保留哪些行为、依据本实例哪些证据、验收与复验场景 |
| configure | 组件能力足够，问题来自调用参数、变体、语义或 token 接入 | 改哪个入口与配置、影响哪些实例、默认值与例外如何验证 |
| refactor | 对外行为可保留，内部状态、数据、副作用或职责组织造成缺陷或改动困难 | 新的内部边界、兼容接口、消费者迁移顺序与回滚 |
| replace | 关键能力缺失或维护代价已证实 | 新实现如何覆盖原行为、适配与差异、依赖成本、替换顺序 |
| remove | 已证实无使用者、重复职责或目标明确取消 | 全部消费者/角色/开关检查、替代路径、清理范围与撤回方式 |
| investigate | 证据不足以确定处置 | 缺什么、补证任务、所需场景、确认后如何选择 |

需要移动、合并、拆分时把它们写成上述处置的具体操作，保留来源与目标定义的映射。同一组件有多个问题时，给一套相容目标方案，避免逐条 FND 产出互相冲突的重写建议。

方案落到具体对象："优化状态管理"要写成状态拥有者、转换与数据失效规则；"抽成公共组件"要写出真正相同的行为、参数化的部分与保留的差异；"统一样式"要写出 token、变体、作用域与需清理的冲突规则；"增强可访问性"要写出角色、名称、键盘动作、焦点、状态播报与验收；"增加测试"要写出要防止回归的用户结果与对应 SCN/CHK。

## 3. 先比行为合同，再比外观

外观相同的两个卡片若数据来源、选择语义与权限不同，共用呈现基础、各自保留业务控制是更省的结果。受控/非受控、默认值、禁用与只读、提交完成事件、异步状态要写成明确约束，让有效组合可以被枚举；靠多个布尔 props 拼状态会产出无人测试过的组合。样式作用域保持可解释，token 替换后检查实际存在的 hover、focus、disabled、error、loading、暗色与高对比模式。加一层 wrapper 只有当接口变化能在局部处理、实例仍能独立演进时才算解耦。

## 4. 写法示例：把任务动作从视觉按钮变成明确合同

以下只作写法示范，不登记为项目事实。

- 共享动作组件的职责限定为呈现名称、可用性与待确认反馈；作业身份与取消结果由业务动作层拥有。
- 按钮输出定义为"用户请求取消该运行"，服务器状态决定终态文案。
- 列表实例与详情实例映射到同一动作合同，各自布局、说明文案与焦点返回位置通过明确参数配置。
- 先补齐"取消被拒绝""响应丢失""取消与完成竞争"三个可回放场景，再迁移一个列表实例与一个详情实例。
- 后端取消协议列为独立依赖；协议未完成时显示待确认状态。

## 5. 根因到实例的影响映射

按根因建 FND，按页面实例保存实际表现：同一个公共弹窗缺焦点约束，20 个调用点是一个根因、20 份实例影响说明。

| 维度 | 记录要求 |
|---|---|
| 共性 | 共享代码或配置如何造成问题，引用最直接证据 |
| 实例差异 | 不同的 props、容器、路由、角色、焦点起点与数据来源 |
| 修改传播 | 一次定义修改自动覆盖哪些调用点，哪些需要手工迁移 |
| 回归风险 | 旧依赖、特殊变体、CSS 覆盖、自定义事件处理 |
| 覆盖结论 | 只对实际验证范围下结论，等价抽样写依据与未覆盖实例 |

跨前端与后端时两侧各自保留任务与完成条件。

## 6. 优先级与依赖图

按具体影响排序：已证实的数据越权、错误对象操作、数据丢失、重复高成本操作、关键流程无法完成在前；关键路径上的键盘不可达、读屏不可理解、错误状态无法恢复按真实阻断程度排序；视觉精度与次要一致性排在已确认业务约束之后，除非它本身造成误操作或访问阻断。高影响但证据不足的问题排为验证任务。共享根因的传播范围、发生条件、可恢复性与暴露频率进入顺序，没有使用数据时标明估计。

每个 TASK 写前置任务、可并行任务与阻塞原因，形成无环依赖。检查"前端等后端、后端又等前端"的循环，用契约约定或隔离验证拆开。语义标记、局部样式配置、场景构造可并行；接口合同未稳定时让多个页面各自发明协议会把缺口扩散。

## 7. 增量迁移阶段

围绕可完整验收的业务闭环拆分，让中间提交保持可运行。

| 阶段 | 输出 | 退出条件 |
|---|---|---|
| 建立基线 | 现有行为、覆盖边界、关键失败场景、必要契约决策 | 能重现关键问题并判断修复是否有效 |
| 解除关键阻断 | 最小范围修复、关键接口或身份边界、必要过渡反馈 | 严重错误被实际阻止或明确隔离 |
| 迁移首个闭环 | 一个页面或流程及其共享依赖、兼容适配、完整验收 | 正常、失败、恢复与关键组合均符合合同 |
| 扩展到其他实例 | 显式消费者清单、差异配置、实例迁移记录 | 范围内消费者均已迁移或有说明地保留 |
| 清理与收口 | 移除已无消费者的旧路径、统一契约与文档、最终回归 | 无悬空调用、无未说明双写、覆盖结论可信 |

兼容适配、功能开关、灰度与双读只在确有并行版本或发布需求时使用；给临时适配写明移除条件。涉及双写时先论证一致性与重复执行风险。不可逆数据迁移与可逆 UI 修改分开：代码回滚恢复不了已删除的数据或已发出的消息，按真实能力写恢复机制。

## 8. 后端与外部依赖

服务端授权、幂等、版本冲突、真实取消、异步作业查询、持久化、流式事件身份、上传校验、导出范围与配额各自建可归责的任务。每个依赖写清：前端观察到的问题与证据及其阻塞的 PAGE/CMP/SCN；所需业务保证与接口语义（没有契约时标明为待商定提案）；负责角色，未知写待分配；前端可独立实现的部分与仍不能承诺的结果；提供方交付条件、调用方集成条件与端到端验收；延期时可接受的降级方案及其用户影响。

前端过渡表现按真实效果描述：隐藏入口、固定延时、内存标记与 AbortController 表达的是客户端行为，服务端授权、幂等与业务取消要由对应层的任务负责。用户要求修复时，先完成已授权且不依赖外部交付的部分，一项外部依赖停不住其余工作。

## 9. 估算

在用户需要排期或信息足以支持时估时，否则给任务相对规模、依赖与先后。每个数字标为粗略估算并给置信度、主要假设、范围与不确定来源，例如"粗略估算：2–4 人日；置信度：低，假设现有接口可复用，未检查历史消费者"。

实现、验证、外部等待与可能返工分开估算；等待后端不等于前端工时。文件数、行数、组件数的线性换算忽略共享根因省下实现、跨实例验证仍有成本这两件事。未知契约、无法启动、依赖冲突与覆盖缺口先安排调查任务，取得证据后更新估算。并行能力与关键路径分开；区间扩大或缩小的触发条件写出来。
