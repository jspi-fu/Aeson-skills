# 发现与逐页工作法

SKILL 第 3–5 节是执行顺序；本文件是发现渠道、拆分粒度、场景等价类与证据核实的细则。

## 1. 输入能力与缺口

从现有会话和项目读取输入，已有信息不再索取。没有项目时可以建立方法，但页面清单不能假造。

| 可访问内容 | 可做 | 必须保留的缺口 |
|---|---|---|
| 源码 + 运行 | 静态、动态与跨边界核对 | 实际缺失的服务、设备、生产配置 |
| 仅源码 | 路由、实现、确定的静态缺陷、目标设计 | 运行交互、真实 API、任务可访问性、实测性能 |
| 仅运行网址 | 观察到的页面、状态、网络与行为 | 隐藏路由、源码结构、服务端控制、构建发布 |
| 截图/设计稿 | 已展示状态的布局、内容、层级风险 | 未显示状态、时序、性能、数据与安全实现 |

production_profile 记录受众、核心任务、操作可逆性、数据风险、身份/租户、支持环境与输入、规模、SEO/SSR、可访问性、发布恢复目标。没有依据时把并发、延迟、内存、合规、SLA 写成待确认条件，继续不依赖它们的检查。

把当前实现、设计意图、接口保证、建议的新约定分开保存；冲突时把冲突呈现出来，选定一边再把另一边判错会掩盖问题。

## 2. 发现页面

静态渠道：框架版本与文件路由、路由表、动态 path、lazy import、重定向与 fallback；layout 与嵌套/平行/拦截路由、404/error/loading 边界、登录回跳；导航、菜单、页内链接、按钮导航、深链接与通知入口；query/hash 视图、wizard、drawer、modal、tab 的独立任务状态；角色、租户、订阅、feature flag、实验与服务端配置控制的页面；iframe、子应用、管理端、子域、移动版本是否在范围内；动态 ID 的有效、缺失、失效、删除、无权限与业务类型等价类。

运行渠道：从已授权入口遍历导航与页内跳转，直接打开深链接并测试刷新、后退、前进；用已授权角色核对差异，没有账号的分支保留 blocked；打开所有可达弹层、tab、折叠、操作菜单、空态、错误重试与二级设置；检查滚动、hover、focus、选中、批量操作后才出现的控件；记录 URL、标题、状态、版本、来源 EV。

对账：列明代码有而运行不可达、运行有而源码未定位、文档有而实现未找到三类差异，确认属于未发布、开关、权限、废弃还是待定位。处理完渠道差异并披露范围限制后，inventory_status 才能写 reconciled。原型中尚未实现的功能登记为产品缺口或待确认规则。

## 3. 拆分粒度

按页面、任务区域、复合组件、叶子职责拆分；文件数量不等于 UI 结构。常见单元：页壳、导航、工具栏、标题说明、表单与字段与帮助与错误与提交取消、表格的单元格类型与行操作与选择与分页、搜索筛选排序、弹窗抽屉浮层、加载空态错误反馈、文件编辑器与媒体图表、AI 流式的回答与引用与工具与作业。共享实现记 DEF，结构不同的使用位置记 CMP；inline 控件记到父文件与符号。

多个 CMP 共享同一 DEF 时，逐实例检查：props 与回调是否合契约；当前对象、身份与租户；name/label/description/ID 及错误引用；父级裁剪、尺寸、滚动、层级、主题与焦点回落；卸载、重挂载、缓存复用、路由切换后的组件身份；实例特殊分支的副作用与安全边界。

## 4. 场景等价类

先定预期再操作，避免把当前实现反推成正确标准。

| 轴 | 应考虑的等价类 |
|---|---|
| 身份 | 未登录、本人、其他用户、其他租户、管理员、过期 |
| 数据 | 未加载、空、1 条、普通规模、约定上限、超限、长文本、缺字段、零、未知枚举 |
| 网络 | 正常、延迟、失败、离线、恢复、乱序、部分成功、超时未知 |
| 时序 | 单次、重复、逆向、中断、并发、离开返回、刷新、多标签页 |
| 输入 | 鼠标、键盘、触控、中文 IME、粘贴、自动填充、辅助技术 |
| 环境 | 支持设备与浏览器、窄容器、缩放、主题、减少动态效果 |
| 生命周期 | 首次进入、后台恢复、长时间使用、旧页面、新旧接口共存 |

按实际分支与单轴边界取值，高风险组合另建场景（过期会话 + 重复写请求、切换租户 + 旧响应迟到、嵌套弹窗 + 键盘 + 触发器被删除）。普通风险用等价类或成对组合降低重复；选择依据与未覆盖范围一并记录，未经说明不对不同页面或不同契约实例抽样。

落进台账时按轴归入 `scenario.context` 的六个键：身份→role，数据→data，网络→network，环境与视口→viewport，输入方式→input，时序与生命周期→lifecycle（刷新、多标签页、后台恢复、新旧接口共存都记在这里）。

SCN 写明身份/版本/环境、具体操作与返回顺序、用户可见与服务端可验证的结果、不得发生的副作用、恢复入口、实际证据。

## 5. 证据核实

确定最小复现条件。静态控制流可以证明确定缺陷，运行时复现另列一栏。

性能结论需要构建模式、设备、网络、规模、操作、指标；条件不全就写待测，大包体积与重渲染次数单独不构成判定。安全结论写清真实信任边界与框架或平台的默认防护；后端不可见时把服务端校验列为待补证。视觉问题区分违反设计基准、影响可读可操作、主观偏好三类，主观偏好按建议而不是缺陷登记。

修复后执行原 SCN 与受影响 SCN，代码改变、静态检查通过、测试完成、上线各记一格。关键交互可录屏或留阶段截图，标注 PAGE/CMP/SCN 与版本。

## 6. 协作

主代理维护唯一 audit.json。子代理按页或领域提交带来源的局部证据，主代理分配与映射 ID、归并根因、保留实例差异并校验。先建全量分母再按批写结果；每批更新说明新增发现、已完成页与实例、实际阻碍、下一步。
