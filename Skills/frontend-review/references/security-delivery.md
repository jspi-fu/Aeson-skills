# 安全与交付审查

把本文件用于真实数据、账号、接口、外部服务、后台任务与取消、上传下载、构建、部署、发布、监控与隐私相关的审查。先识别适用边界，再按每一类核查；纯静态展示页只取适用条目。规则与项目版本按 source-register.md 的来源标识核查。

## 先确定授权、证据与责任

- 共用控制的结论覆盖它的全部调用点：逐入口、逐角色、逐租户、逐缓存策略分别复验，整站通过需要各入口各自的证据。

## 01 检查对象、字段、租户与接口授权

- 判定边界：后端授权结论取自可信服务层的实际规则与响应；UI 隐藏与前端 role 判断只证明展示控制。缺后端源码时记为未见证据。先确认数据原本应保密，合法公开数据按公开范围判定。
- 验证动作：用获准身份比较匿名、本人、同租户非所有者、跨租户与管理员在读取和写入上的差异；先用夹具或集成测试覆盖直接调用接口的路径，覆盖路由 guard、字段序列化、租户来源、下载与导出、GraphQL resolver。
- 重构机制：在可信服务层按主体、动作、对象、字段、租户执行授权并默认拒绝未明确允许的访问；租户从可信身份解析；响应字段最小化；前端消费权限结果并显示一致反馈。
- 复验：合法访问成功、越权访问失败且不返回受限字段；覆盖列表、详情、搜索、批量、导出与静态附件；记录服务器证据或写明剩余 blocked。
- 来源：OWASP-AUTH、OWASP-FE。

## 02 检查会话与浏览器存储

- 判定边界：本地登录展示不等于可信身份；普通偏好存在本地不是缺陷。长期会话凭据可被页面脚本读取时按威胁与架构评估，HttpOnly 只改变 Cookie 的暴露面。
- 验证动作：在隔离账号中重现刷新、多标签、令牌失效、A 退出后 B 登录；观察过期请求与缓存放大。检查 cookie 属性、令牌有效期与 localStorage、IndexedDB、查询缓存的用途；设备撤销只在授权范围内验证。
- 重构机制：使用项目身份体系的受支持流程；合并并发刷新并限制失效重试；缓存按主体／租户划分并在切换时清理；跨端撤销要求服务端会话支持，本地事件只覆盖本端。
- 复验：账号／租户切换后无前一身份数据残留；过期不无限重试、不丢必要草稿、不错误恢复旧身份；本地同步与跨设备撤销分别标明验证到哪一层。
- 来源：OWASP-HTML5、OWASP-AUTH。

## 03 检查数据库授权与 RLS

- 判定边界：客户端按平台设计直连受保护 API 是正常架构。anon／publishable key 与 service-role／secret key 是两类东西，公开 key 出现在浏览器不构成泄密。RLS 已启用只证明开关存在，规则正确性看各操作的 policy 与夹具结果。
- 验证动作：在隔离数据库以 anon、authenticated、所有者、他人、跨租户夹具跑 SELECT、INSERT、UPDATE、DELETE；让受影响表和真实策略进测试，无关示例表不产生结论。读取 schema、grants、存储桶规则、视图／函数权限与客户端和服务端使用的角色。
- 重构机制：表级 grants 与行级 policy 同时匹配业务；按操作限制主体与数据归属；检查可绕过 RLS 的服务角色、视图与函数；配置进迁移，新增表有安全默认值。
- 复验：授权路径有正确数据、拒绝路径无数据无写入；覆盖归属字段修改、批量入口与附件。缺数据库证据时按 blocked 要求脱敏 migration／policy 导出与测试结果。
- 来源：SUPABASE-RLS、OWASP-AUTH。

## 04 区分公开配置与私密凭据

- 判定边界：私密性看值是否会进入浏览器可读的位置；.env、代码混淆、Base64、代理路径、不提交 Git 都不构成浏览器内保密机制。按设计公开的项目标识保持公开，public key 的名称本身也不是安全保证。
- 验证动作：从生产模式构建产物确认哪些配置进了浏览器；追踪模型、支付、邮件、存储各自 key 的类型与能力；对照服务商文档区分公开标识与私密凭据。只摘录变量名和位置。
- 重构机制：私密凭据只放可信运行环境与秘密管理；私密调用由受控后端执行，按最小权限与配额；确认泄露时给出轮换、影响核查与从最新页面移除三项。
- 复验：新旧构建、source map 与日志均不含私密值；用测试凭据证明新调用链可用。source map 是否公开按项目源码公开策略判断，密钥判定只看实际值是否进入浏览器。
- 来源：VITE-ENV、OWASP-FE、GHA-SECURE。

## 05 检查运行边界与服务端防护

- 判定边界：执行边界由实际部署决定，SSR、server 文件名或 Edge 部署只证明代码所在位置。幂等由可信层的幂等键与去重存储保证，按钮状态只是重复触发的体验控制；作业与取消的状态合同见 [state-data.md](state-data.md) 第 11 节。
- 验证动作：核对价格、资源额度、文件大小、目标 URL 与业务规则在哪一层执行；把"服务端是否真的停止、真的去重"作为独立于前端状态的断言。
- 重构机制：可信层校验输入、权限、业务规则与资源限制；区分失败与结果未知并提供状态查询；抓取、模型工具与代理能力按能力边界约束目标与行为。后端缺少取消确认、幂等、事件游标或产物查询时建独立接口任务。
- 复验：隔离环境验证同一意图的重复请求、回包丢失、部分成功、取消后查询与暂时性失败的真实副作用次数。没有后台证据时结论只覆盖前端状态处理。
- 来源：RFC9110、OWASP-FE、OWASP-AUTH。

## 06 按架构检查 CSRF 与 CORS

- 判定边界：CSRF 结论建立在身份是否由浏览器自动携带与服务器如何校验之上；框架内置控制、强制自定义头与严格来源策略都可以是等效方案，JWT／JSON／SameSite 也不自动等于安全，按具体架构与接口判定。CORS 约束的是跨源请求能否发出与响应能否读取，对象授权另算。
- 验证动作：沿真实写操作检查客户端提交与服务端校验如何配合；在获准的隔离来源与测试账号验证跨站请求的成功条件；把浏览器能否发出、服务器是否执行、响应能否读取三件事分开。记录 cookie SameSite、Origin／Referer、Fetch Metadata 与实际 CORS 响应头。
- 重构机制：优先启用适用框架的 CSRF 机制；在服务端验证每个受保护的变更请求；精确约束可信来源与凭据，联调放宽设置回收条件。
- 复验：合法同源与业务跨域流程可用，未授权跨站变更被拒；覆盖登录、上传、表单、JSON API 与 GET 误用。缺会话／部署证据时按 blocked 列出所需响应头与服务端配置。
- 来源：OWASP-CSRF、FETCH、OWASP-HTML5。

## 07 检查 Markdown、富文本与 AI 输出

- 判定边界：注入结论需要不可信来源、危险输出位置与可执行路径同时成立；普通 Markdown 与开启 raw HTML、动态组件的渲染是两种风险，未清洗的原始字符串本身不构成漏洞，框架文本转义只覆盖文本节点。模型输出按不可信数据处理，模型文本不是服务器执行证明；流式过程的分帧、去重与完成条件见 [state-data.md](state-data.md) 第 12 节。
- 验证动作：在隔离渲染器用无外传、无破坏的样本验证文本转义、HTML 清洗、链接协议与嵌入限制；覆盖流式半段、最终结果、编辑预览、历史记录与导出。检查 raw HTML、渲染插件、代码高亮、SVG 与动态组件能力。
- 重构机制：默认使用安全文本绑定；确需 HTML 时使用维护中的 sanitizer 与明确允许列表；按输出上下文处理 URL 与属性；允许执行的用户代码放进隔离环境。
- 复验：危险能力不可执行且正常格式、链接、代码块仍可用；核对 sanitizer 与插件的实际版本；按协议帧与重复事件注入后半段消息不断裂、不串会话、不出现假完成。
- 来源：OWASP-FE、OWASP-HTML5。

## 08 检查外链与重定向

- 判定边界：URL 安全性由解析结果与目标策略决定，字符串包含域名和统一 HTML 转义都不是判断依据。允许外链是产品能力，先看承诺、信任目标与数据边界。
- 验证动作：用本地安全目标验证相对路径、协议、跨源、编码与多重重定向的处理；检查凭据、文档标识与敏感 query 是否被附进外部请求。收集 returnTo、next、redirect、下载链接与用户提供 URL 的解析与最终导航方式。
- 重构机制：使用 URL 解析与精确的协议／目标策略；约束身份回调跳转；按目标浏览器与打开方式处理 opener；敏感导航场景设置合适的 referrer 策略。
- 复验：业务允许的外链正常，未授权跳转与凭据外带被阻断；在承诺的浏览器上验证实际导航结果与 opener 行为，静态属性作为补充线索。
- 来源：HTML、OWASP-HTML5、RFC9110。

## 09 检查 iframe 与 postMessage

- 判定边界：风险由载荷敏感度与赋予的能力决定；`*`、缺 sandbox 或使用 iframe 是风险信号，确认结论要落到具体能力。身份取自连接与协议核验，不取自消息里的 role／userId；origin 判定使用精确匹配。
- 验证动作：在隔离父子页面尝试来自不可信窗口、错误 origin、错误结构与过时会话的消息；验证重定向后接收方的变化。检查 iframe 源、sandbox／权限、共享 origin、消息目标与接收校验。
- 重构机制：明确允许的发送／接收来源与消息 schema；最小化 iframe 能力；需要执行不可信内容的页面使用隔离 origin；来源不可固定时记录替代验证机制与威胁模型。
- 复验：合法嵌入与登录消息正常，来自其他窗口的消息不能变更身份、取走敏感数据或触发高权限操作。
- 来源：OWASP-HTML5、HTML。

## 10 检查上传、下载与导出

- 判定边界：服务器校验与对象权限是判定基准，前端 accept、扩展名检查和预校验属于输入体验层。文件可下载是否构成暴露，看预期的公开范围与链接授权方式。上传按字节传输结束与服务端处理完成两阶段判定；下载按生成中、链接可用、链接过期三个状态判定。
- 验证动作：用小型无害文件与合成数据验证类型、大小、归属、过期链接、取消与恢复；队列条目保持稳定的文件身份，同名不同文件与断网后仍能对应到原任务，支持断点续传时才检查恢复。在授权环境检查直接接口路径，不向真实第三方上传私密内容。
- 重构机制：服务端校验文件与对象权限并设置适当资源限制；需预览的主动内容做隔离；按用途设定短时授权下载；释放预览资源、清理临时文件、保留可恢复进度，重试按幂等约定；导出核对范围、时区、单位与界面筛选，表格按目标格式处理公式注入与文件名；下载链接、预览与导出按钮各自定义动作与结果状态。
- 复验：合法文件可用、越权下载被拒、取消与重试不遗留错误业务状态；实际打开隔离样本比对内容与记录数，让临时链接过期后验证恢复入口与错误反馈。未取得存储策略与可控账号时按 blocked 写明缺口。
- 来源：OWASP-AUTH、OWASP-FE、SUPABASE-RLS。

## 11 检查依赖与供应链

- 判定边界：可利用性由受影响版本、项目可达路径与维护者公告决定；audit 条数、包名观感、版本陈旧或存在 CVE 只是线索，锁文件、下载量与“官方包”也不构成安全证明。第三方脚本的风险按它实际取得的运行能力评估，来源域名是其中一项。
- 验证动作：核对实际解析版本与直接／传递依赖；必要时用官方公告确认适用条件、受影响版本与可达路径；运行安装前查看安装脚本。检查 manifest、锁文件、运行时版本、远程 CDN 脚本、许可证与 CI 第三方 action 的凭据范围。
- 重构机制：移除不必要依赖；锁定并可复现安装，安排受控升级；限制第三方脚本与 CI 权限；action 采用可信来源与不可变引用；漏洞修复与兼容性回归一并规划。
- 复验：依赖树、构建、关键路径与授权配置符合目标；保留修复前后版本证据。告警处理以可达性证据为准，逐包给出依赖评估与回归范围。
- 来源：NPM-CI、GHA-SECURE。

## 12 检查开发、预览与生产构建

- 判定边界：门禁结论来自实际执行的脚本链与退出码。dev 页面能打开与 build 成功是两件事；Vite 本身只转译 TypeScript，类型检查是否执行看项目 build 脚本有没有另行调用 tsc 或其他 checker，其他框架按对应版本查证。
- 验证动作：先读 package scripts、框架／构建器版本、tsconfig、CI 与部署配置，确认命令副作用后运行项目实际的 typecheck、lint、测试与生产 build；核对退出码与完整脚本链；用生产产物验证深层路由刷新、资源 base、懒加载、环境配置与目标浏览器。区分 dev server、预览构建、生产服务、mock、代理与真实 API。
- 重构机制：把类型／静态检查与构建组织为明确门禁；分离预览与生产的账号、API、回调与秘密；校验必填配置；为本地代理与生产网关建立一致契约。
- 复验：在干净环境完成目标生产构建并运行产物；保留版本、命令、退出状态与验证范围。没有部署访问时，生产域名、响应头与回调验证按 blocked 记录。
- 来源：VITE-FEAT、VITE-BUILD、VITE-ENV、TS-BASICS、NPM-CI。

## 13 检查缓存与 Service Worker

- 判定边界：缓存正确性按存储层判定，HTTP／CDN、SSR 数据、内存查询缓存、浏览器存储与 Cache API 各有清理路径；no-store 只作用于 HTTP 层，Cache API 条目由应用代码管理。身份与租户隔离要同时落在服务端授权与缓存语义两处，缓存键存在不能替代授权检查。按数据敏感性与新鲜度要求决定策略，静态资产与个性化数据保持可用。
- 验证动作：在隔离环境比较首次访问、旧标签、离线、重新上线、账号／租户切换与新版本发布；检查缓存中是否留有不应持久化的数据；盘点个性化响应的缓存键与头、worker scope、更新与激活策略。
- 重构机制：分开静态资产与个性化数据策略；把必要身份／租户维度加入缓存语义；显式排除或安全清理敏感 Cache API 内容；设计 worker 更新、旧客户端兼容与受控恢复流程。
- 复验：切账号看不到他人数据，离线与恢复不覆盖较新结果，旧标签能安全升级；清理路径保留真实用户未提交草稿。未见 CDN／worker 配置时注明覆盖边界。
- 来源：RFC9111、MDN-CACHE、OWASP-HTML5、VITE-BUILD。

## 14 检查发布与回滚兼容性

- 判定边界：回滚范围按静态产物、配置、数据库迁移、外部接口与已完成交易各自的独立性界定；平台提供回滚按钮只证明平台层能力，应用恢复能力看兼容窗口与流程。
- 验证动作：在已授权的预览／隔离环境演练新旧客户端与接口组合、旧动态 chunk 加载、配置变动与回滚；没有发布授权时先完成文档与兼容矩阵审查。关联 commit、构建、部署、迁移与监控版本。
- 重构机制：保留可恢复产物并设置兼容窗口；破坏性接口与数据迁移分阶段处理；按风险采用分批发布或功能关闭，预设验证指标、停止条件与负责人。
- 复验：回滚后关键旅程、身份与数据仍可用；新版本问题没有被旧配置重现。记录平台层与应用层各自承担什么，未实际演练时回滚结论保持待验证。
- 来源：VERCEL-ROLLBACK、VITE-BUILD、RFC9111。

## 15 检查日志、埋点与隐私

- 判定边界：采集结论以实际发出的事件与接收端为准，配置名与默认脱敏开关不改变实测结果；允许列表内的匿名诊断是正常能力。产品政策、合同要求、适用法律与工程建议分开表述，法律结论按需另行核实。
- 验证动作：用合成敏感标记触发成功、校验失败与异常，检查实际发出的事件与获准查看的接收结果；验证屏蔽与采样路径。核对 SDK 版本、目的、接收方、过滤与访问策略，以及 session replay、截图、表单字段与对话采集范围。
- 重构机制：采用字段允许列表与最小必要采集；在源头排除 token、密码与敏感内容；明确回放遮罩、身份关联、访问权限、保留期与删除流程；让监控故障不拖垮主要业务。
- 复验：必要事件可关联、敏感标记未外发、第三方不可用时主流程仍可用；没有接收端证据时只报告发送侧已验证的范围。
- 来源：OWASP-LOG、GHA-SECURE。

## 16 检查错误边界与监控

- 判定边界：捕获范围按框架版本文档确认，React Error Boundary 覆盖渲染，事件处理、一般异步回调、SSR 与边界自身错误需要各自的处理路径，transition 等例外查对应版本；已捕获的错误需要显式上报才能进入监控。监控数据只覆盖已上报的部分，初始化前失败、浏览器终止、断网、采样与拦截都可能表现为无数据。
- 验证动作：在隔离环境分别注入渲染异常、事件异常、异步拒绝、资源加载失败与业务返回失败；确认用户反馈、恢复入口与监控记录均发生。盘点根级异常、请求错误、source map、release 标识与告警规则。
- 重构机制：按可独立恢复的区域布置边界；对业务失败、异步任务、请求与渲染分别处理；主动记录需要诊断的已处理异常；关联脱敏请求标识、版本与交互；按风险补真实用户与关键旅程监控。
- 复验：出错区域可恢复、其余区域可继续；生产构建也上报且 source map 与 release 匹配。
- 来源：REACT-BOUNDARY、OWASP-LOG。

## 17 检查 CI、测试与证据含义

- 判定边界：证据强度按断言对象判断，截图一致、退出码为零、用例跑绿、行覆盖率各自只证明自身口径。命令是否实际执行、有无 skip、空测试、错误吞掉与无限重试决定“跑绿”的含义。覆盖率注明分母、环境与排除项；自动无障碍检查之外仍需键盘、焦点与辅助技术人工验证；模拟设备与目标真机、浏览器 E2E 与接口越权审计、无真实后端时的持久化与权限结论各自分列。
- 验证动作：追踪核心路径是否断言最终业务结果，例如保存后重新获取；在可控真实服务中运行少量关键链路，用 mock 覆盖异常并清楚标注被替代部分。区分单元、组件、契约、集成、E2E、视觉、无障碍与性能证据，读取真正被 CI 调用的脚本、断言、mock 与排除规则。
- 重构机制：把高风险纯逻辑、状态组件、接口契约与关键旅程分层验证；隔离账号与测试数据，用用户可见行为定位与等待断言；保存失败 trace；让测试权限与生产凭据分离。
- 复验：让修复对应的反例先可证明失败，再验证修复与合法路径；测试范围扩到受影响依赖和必要门禁。
- 来源：PLAYWRIGHT-BP、PLAYWRIGHT-A11Y、GHA-SECURE。
