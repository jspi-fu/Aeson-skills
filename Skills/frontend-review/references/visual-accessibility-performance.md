# 视觉、可访问性与性能验证手册

## V01 先确定证据与适用范围

- 按主 Skill 的审查范围与页面、实例清单选取本文件检查项，与逐组件手册组合执行。
- 核对用户指定的浏览器、设备、语言、主题、辅助功能和性能目标并直接沿用；约束不全时先查真实产品定位、现有配置与可见数据，写下工作假设，继续不依赖缺失信息的检查。
- 将缺少移动端适配与“仅承诺桌面、指定最低宽度”区分；对后者检查低于边界时是否仍有可理解提示，边界之外不扩成全设备支持。
- 把基础语义、键盘与输入法当作已支持交互的实现质量检查，“不是出海产品”不构成不适用理由。
- 保留设计者已做出的交互决策，仅在证据表明不可用、互相冲突或超出实现能力时给出明确替代；反馈、中断与失败路径的观察使用隔离样本、现有 fixture 或已授权记录。

## V02 建立逐页视觉基准

- 按每个页面定位可用设计来源：用户截图、设计稿、已确认设计系统或现有产品约定；参考冲突时记录版本与冲突点并沿用用户确认的当前目标，没有参考时检查内部一致性、层级与可用性并把结论写为设计建议，不给“还原度 95%”一类无依据数字。
- 比较前对齐参考与实测的视口、缩放、内容、字体、主题与状态，避免把数据差异判成 CSS 缺陷。
- 为每页建立默认、有内容、空白、加载、错误等实际可达状态的基准；仅有默认截图时标明其余状态没有设计依据。
- 对重要交互实例补齐焦点、按下、忙碌、无效、只读等适用变体，并按已有原型检查滚动后的固定区、页底操作、弹层、展开内容与跳转后状态。
- 截图工具可用时保存相同尺寸的基准与当前图，比较差异区域并用实际 DOM 或样式证据确认根因；只遮罩时间戳等已知非确定内容，对抗锯齿、系统字体渲染等环境噪声说明限制，像素级误差按噪声处理。

### 按层记录差异

| 层 | 检查动作 | 区分的问题 |
|---|---|---|
| 信息结构 | 核对标题、分组、阅读顺序、主次操作 | 内容缺失与单纯间距偏差 |
| 布局 | 检查容器、列宽、边距、对齐、溢出与固定区域 | 定位布局规则而非逐个像素补丁 |
| 字体 | 检查实际加载字体、字重、字号、行高、回退 | 字体未加载与字号写错 |
| 色彩 | 检查状态色、背景叠加、边框、焦点和主题 | token 错误与透明度组合问题 |
| 媒体 | 检查比例、裁切、清晰度、占位和加载后尺寸 | 素材问题与容器规则 |
| 状态 | 比较正常、错误、加载和禁用时的稳定性 | 样式缺失与状态模型错误 |

## V03 检查样式体系与真实内容

- 追踪样式来自 design token、共享定义、页面覆盖还是运行时内联属性，在最小正确层级修复；默认样式、重置样式、作用域与加载顺序的冲突通过理清来源解决，靠增加选择器强度只会掩盖冲突。
- 比较同一语义在不同页面中的字号、间距、圆角、边框和状态色；保留确有业务理由的差异，在主题支持范围内逐一核对语义 token。
- 区分图标自身尺寸与点击区域，让名称、图标和加载指示在所有状态下对齐；检查固定高度的文本与容器在多行内容、错误信息和系统放大文字下的裁切，检查 flex/grid 的最小尺寸、长词折行与溢出规则，为需要完整读取的内容提供实际入口。
- 覆盖 0、空字符串、null、缺失字段、长 ID、超长文件名和长 URL 的实际渲染，被截断内容保留可读入口；对金额、比率、日期和单位核对显示精度与接口含义，显示格式与存储和计算规则分别定义。
- 在已有多语言支持时检查最长文案、复数、CJK 换行、数字分隔和字体回退；支持 RTL 时检查混排及逻辑方向。
- 检查真实内容排序与 DOM 阅读顺序一致，CSS order 不让屏幕顺序与键盘顺序分离；对列表和表格检查空、单项、典型规模、长内容、部分错误，规模按用户数据和产品限制确定。

## V04 检查微交互与中断

- 将反馈拆成“输入已被接收”“任务正在执行”“结果已确认”三类，从按钮状态、焦点、布局、请求和最终结果等实际事件核对各自文案与出现时机，并确认同步重计算没有阻止忙碌状态被绘制。
- 让 hover、focus-visible、active、selected 和 disabled 各自有独立作用，焦点与永久选中区分开。
- 对关键操作在进入、执行和结束阶段分别尝试反向动作，只执行产品承诺且已授权的中断；在过渡未结束时快速反向开关，检查动画结束回调是否把新状态覆盖成旧状态。
- 任务失败后让按钮、输入、反馈和焦点恢复到可继续操作的状态；旧 toast、表单重置或自动跳转不干扰新一轮流程。
- 反馈用词与实际确认到的终态一致，取消以收到的服务端确认收束。
- 自动滚动只在用户正跟随内容或明确触发时执行；用户上翻阅读时保留位置并提供返回最新入口。
- 动画时长遵循现有设计与实测需求；存在减弱动态效果偏好时用替代反馈保留状态含义，状态含义不依赖动画本身。

### 用动作矩阵检查反向路径

| 起始动作 | 在何时中断 | 核对结果 |
|---|---|---|
| 打开弹层 | 进入动画中关闭，再次打开 | 显隐、焦点、滚动锁与背景可操作性 |
| 发起查询 | 旧请求未返回时换词或清空 | 结果仍对应当前查询 |
| 提交表单 | 超时、后退、再次提交 | 保存状态、草稿和真实创建次数 |
| 拖拽移动 | 移出边界、松手前取消 | 原位置、当前选择和指针清理 |
| 开始流式任务 | 切会话、断网、点击停止 | 消息身份、恢复和实际任务状态 |
| 删除当前记录 | 删除成功后返回列表 | 焦点、页码和剩余选择 |

## V05 组织响应式组合

- 从支持范围生成每页测试矩阵，保留所有页面与适用状态的清单后再决定组合覆盖深度；空间大时采用代表性或成对覆盖并声明未覆盖组合。每页先覆盖正常布局及各实际断点两侧，在控件布局或导航模式发生变化处补边界值与相邻宽度，对高风险实例增加窄宽度、长内容、错误或展开状态的组合。
- 在已有桌面支持时检查窄窗口、宽屏和浏览器缩放；在已有手机支持时再检查触摸、横竖屏与软键盘。浏览器设备模拟与真机验证分开记录：模拟视口和触摸可证明布局响应，真实输入法、浏览器外壳及软键盘行为需要真机。
- 对文本放大与重排按适用的 WCAG 条件检查，对本质需要二维表达的内容单列例外并说明理由；在移动端检查地址栏展开收起、软键盘弹出、底部安全区域和视觉视口，先识别现有布局需求再选择视口单位或能力适配。
- 在多个嵌套滚动区域中确认触摸、滚轮和键盘可把必要控件带入视野；在旋转和 resize 后检查弹层锚点、表格宽度、图表尺寸和当前编辑内容。
- 对弹窗中的输入区检查“小屏 + 错误文案 + 软键盘”；对宽表检查“长单元格 + 固定列 + 缩放”；对产品明确不支持的环境标注边界与实际降级表现。

| 轴 | 选择方式 | 增加组合的条件 |
|---|---|---|
| 视口 | 声明的最小、典型、最大与布局断点 | 控件布局或导航模式发生变化时增加边界 |
| 内容 | 空、典型、最长合法值、缺失与错误 | 组件使用固定尺寸或截断时增加长内容 |
| 输入 | 覆盖键盘；按支持范围增加鼠标、触摸、输入法 | 悬停、拖拽、快捷键、软键盘相关组件增加组合 |
| 偏好 | 按支持范围检查主题、减弱动态效果、缩放 | 动画、主题覆盖、状态色或固定高度处增加组合 |
| 状态 | 当前控件可达的加载、错误、只读、禁用 | 状态改变尺寸、焦点或可用动作时增加组合 |
| 身份 | 已授权的角色、所有者与非所有者测试数据 | 实例根据权限隐藏、禁用或切换内容时增加组合 |
| 网络 | 正常、延迟、失败、重连的受控条件 | 远程搜索、上传、流式和长任务中增加组合 |

## V06 检查层级定位与滚动

- 先标记每个滚动容器、固定区、sticky 区、transform 祖先、裁切容器和浮层挂载位置，再按父级 overflow、层叠上下文、定位参照、viewport 变化或滚动同步定位被遮挡的原因，z-index 只在层叠上下文确认是原因时调整。
- 对模态内容统一管理背景不可交互、焦点边界和滚动锁，嵌套弹层由最上层处理 Esc、外部点击和焦点返回，其余层只处理自己收到的事件；对非模态浮层保留合理背景操作。
- 在打开和关闭弹层后比较布局，滚动条出现消失造成的横移按现有布局选择稳定处理。
- 对固定页头、吸底工具栏与 cookie/系统横幅检查焦点是否被遮挡，把内容滚动到合理可见区域；区分“焦点组件不被作者内容完全遮住”的 WCAG 2.2 AA 要求与更充分的可见性目标，按等级写结论。
- 在弹层内部滚至顶部和底部后继续滚动，背景行为符合产品预期。
- 对程序化 scrollIntoView 或滚动恢复确认选择的容器；在历史数据前插、图片加载或字体替换后观察阅读位置，聊天和日志采用明确的跟随与锚点策略。
- 在页面回退时核对产品承诺的筛选、页码、滚动位置与焦点落点；在拆分面板中检查最小宽高、可收起区域和键盘调整，主内容仍可完成任务。

## V07 检查输入法与编辑行为

- 对中文、日文、韩文等已支持输入法，在真实目标浏览器或可用测试环境检查组合输入，记录 compositionstart、compositionend 与键盘/输入事件的实际顺序；纯英文 fill 只覆盖设值，覆盖不到候选确认。
- 在候选词尚未确认时按 Enter，核对不会误提交或发送；再按产品约定正常提交。
- 检查组合输入期间的实时校验、防抖搜索和格式化不覆盖候选文本、不重复请求、不移动光标。
- 结合框架事件封装与目标浏览器行为验证 isComposing 判断的实际覆盖范围，把它当作必要而非充分处理；废弃 keyCode 分支只在有明确兼容证据和支持范围时添加并写明兼容对象。
- 对输入覆盖粘贴、剪切、撤销、重做、光标中部插入、选区替换、自动填充，密码和验证码允许产品规则支持的粘贴、管理器与自动完成；在支持语音时增加语音输入。
- 写清 Enter 提交与多行换行策略，保留系统、编辑器与辅助技术依赖的快捷键。
- 对数字和格式化输入检查负号、小数点、未输入完成的分隔符等中间态，在确定时机解析而不是每次键入都重写。
- 存在字数限制时区分用户可见字符、字节和 token；需按字素计数时验证相关 API 或库的目标支持。
- 在切页、切记录和组件重挂载后核对输入值、光标与选区，区分业务要求的重置与意外丢失。

### 最小输入验收序列

1. 用已支持输入法输入有多个候选词的文字，按 Enter 确认候选，观察是否误触发送或提交。
2. 在文本中间插入一段内容，执行撤销再重做。
3. 粘贴一段含换行、emoji 或边界数值的合法样本。
4. 触发一次受控校验或提交失败，继续编辑并再次提交。
5. 核对显示值、请求值、光标、错误提示和当前实体身份。
6. 没有真实输入法环境时，把整个序列标为待验证。

## V08 完成键盘与焦点路径

- 从地址栏进入或从页面起点开始，用键盘完成页面主要任务；记录必须使用鼠标才能继续的位置，以及只检查 tabindex 存在不足以证明键盘可用的实例。
- Tab 顺序跟随阅读顺序：检查正向与反向 Tab、可见焦点样式，以及跳过重复导航直达主内容与标题的路径。
- 区分焦点、选中、展开、悬停和当前路由，核对每种状态对应实际 DOM 属性与可访问语义；交互控件由可聚焦的原生语义承载，按钮优先恢复原生行为、链接保留真实导航。
- 对自定义复合控件先确定模式，再检查该模式的方向键、确认、取消和边界；方向键拦截只用于该模式确需方向语义的场景。
- 对禁用策略核对是否需要可被发现的原因；采用 aria-disabled 时仍在动作路径上正确阻止执行。
- 打开模态时检查初始焦点、遍历边界与关闭后焦点，触发元素消失后把焦点移到合理下一步；多层 Esc 由当前上下文处理，正在输入时一次 Esc 只结束当前层的动作。
- 非模态弹层保持可自由 Tab 离开；确需编辑快捷键的编辑器提供可退出的焦点路径。
- 删除、移动、分页、筛选和内容重排后确认焦点依然存在且有上下文；路由转换、错误摘要和后台更新不把焦点移到 body 或不可见元素。

## V09 检查屏幕阅读器与语义

- 从实际 DOM 或可访问树检查名称、角色、值、状态和关系，辅助技术体验由可访问树和读屏结果确认而非截图推断；检查标题层级、landmark、列表、表格表头和表单分组，把有业务含义的结构用适当语义表达。
- 检查每个图标按钮、同名行操作和字段的名称，为重复操作提供当前对象上下文；字段身份由关联的 label 承载，placeholder 作为输入提示的补充，帮助与错误信息通过引用关联到字段，错误状态同时给出文字说明而不只有红框。
- 检查 aria-expanded、aria-checked、aria-selected、aria-current 等值跟随真实状态；检查 ID 唯一性、label/description 引用与动态挂载，共享组件自身正确不代替调用处传入的 ID 正确。
- 在完整页面中检查 dialog 名称和背景处理；aria-hidden 区域不保留用户正需要操作的焦点。
- 对成功、错误、结果数量与后台更新按重要程度选择播报级别：高优先级 live region 只承载状态变化本身，页面主体与逐段输出留在普通阅读路径。
- 对虚拟列表或懒加载内容检查阅读顺序、位置及总量信息，必要时提供适合业务的替代访问方式；对图表、信息图、视频和复杂文档核对等价信息路径。
- 在真实读屏器可用时记录具体软件与浏览器组合，完成主任务、表单失败和弹层打开关闭路径；没有读屏器时记录 DOM 语义与自动扫描结果，把实际播报、浏览模式和组合控件体验标为待验证。
- 自动扫描的“未发现问题”限定在该扫描规则和被测状态；单页通过要回到页面与流程清单核对缺口。

## V10 检查视觉偏好与动态效果

- 对必要文本与真实背景做对比度测量，测量对象包含叠加背景、渐变、透明度与主题组合后的实际结果；按适用成功准则分别判定普通文本、大字、非文本控件与不活跃元素。
- 检查状态是否同时通过文字、图标或形状表达，颜色、闪烁与位置变化作为补充。
- 检查交互目标的实际点击区域及邻近间距；按 WCAG 2.2 AA 的 24×24 CSS px 要求及例外判断。
- 将 44×44 CSS px 标为更强目标或 WCAG AAA 相关要求。
- 在用户开启 prefers-reduced-motion 时检查视差、平移、缩放、自动滚动和循环装饰；减少可能引起不适的运动，并用替代反馈保留可感知的状态含义。
- 在产品存在自动播放、轮播或持续更新时提供暂停、停止或隐藏等适用机制；在目标平台支持 forced-colors 或高对比度设置时检查焦点、边框、图标与选中状态。
- 放大文字并增加文本间距，检查遮挡、重叠、裁切和控件可达性，按实际适用条件记录例外。
- 对动画和媒体核对闪烁风险，不确定效果按官方准则核查后判定；系统偏好模拟与实际系统设置测试分开记录。

## V11 按架构检查SSR与公开页面

**适用条件：** 只有项目已经使用或确有业务需求时检查 SSR、预渲染、hydration 和公开搜索收录。

- 先识别页面采用客户端渲染、服务端渲染、静态生成还是混合模式，记录路由和组件的实际执行边界。
- 对纯内部后台优先检查登录、首屏可用、刷新和深链接；搜索索引、sitemap 与 SSR 只在有收录需求时纳入范围。
- 对 SSR 页面分别查看初始 HTML 和客户端接管后的结果，在相同数据和区域设置下核对结构与内容一致性。
- 检查时间、随机值、语言、时区、浏览器专属 API 和不合法结构造成的初始输出差异；对读取 window、document、屏幕尺寸或本地存储的路径确认执行时机，按实际框架机制隔离浏览器能力。
- client 标记的实际含义按当前框架文档确认，不等同于“绝不在服务器生成初始 HTML”。
- 对 hydration 警告定位具体差异节点；suppressHydrationWarning 只用于时间戳等本质上无法一致的内容。
- 检查服务端与客户端重复取数、共享缓存和身份数据是否一致，对个性化内容核对缓存隔离。
- 对无脚本、脚本失败或延迟加载时的表现按产品承诺评估；在公开收录需要时检查真实链接、唯一标题、描述、canonical 和正确状态码，验证不存在资源返回正确状态。
- 承认 Google 可以执行 JavaScript；不要用“CSR 无法 SEO”作为架构论据。
- 对 SSR/SSG 建议写明预期收益、服务器成本、缓存与数据新鲜度约束，再给最小可行迁移范围。

## V12 建立性能实测协议

- 先把“慢”定位为加载慢、响应绘制慢、接口等待慢、长时间使用变慢或布局不稳定，再把每个疑点绑定具体页面、动作、数据规模和设备。
- 优先测项目实际生产构建，开发模式数据用于定位并说明其局限。
- 记录版本、浏览器、设备、网络、CPU 模拟、冷暖缓存、登录状态和样本；保留改动前基线再对同一路径复测，比较时保持条件可比，没有基线时注明无法量化收益。
- 根据风险选择重复次数并报告波动，取最能代表用户实际经历的取值；将工具结果、用户体感与后端耗时关联，识别瓶颈发生在哪一段。
- 对同页持续交互检查输入、搜索、切换、滚动和任务输出；对长期使用检查重复打开关闭、切记录、后台恢复和任务完成后的资源回收。
- 在已有且授权的真实用户监测可用时，按页面、设备和版本查看分布；缺少真实用户数据时用实验室结果定位风险，并说明线上分布尚未验证；对敏感界面只记录必要的性能元信息。

### 选择正确指标

| 问题 | 使用证据 | 需要区分开的 |
|---|---|---|
| 首屏关键内容晚出现 | LCP、资源链、图片字体、服务端响应与渲染 | 本地热缓存速度与首次访问 |
| 点击或输入不及时显示反馈 | INP 或对应交互的事件与主线程轨迹 | INP 与接口从发出到返回的总时长 |
| 布局突然跳动 | CLS 及具体偏移来源 | 初次载入之外的持续偏移 |
| CPU 同步任务阻塞 | 长任务与函数调用、样式布局和绘制 | 已设置 loading 状态与实际已绘制 |
| 大列表与长文档卡顿 | DOM 规模、渲染频率、查询与数据加工 | 条目数量与实测瓶颈所在 |
| 长会话占用持续增长 | 多次生命周期后的保留对象与资源 | 一次堆内存上升与稳定泄漏 |
| 请求慢但界面响应正常 | 排队、网络、后端、缓存与数据转换分段 | 前端渲染耗时与网络后端耗时 |

- 引用 Core Web Vitals 时核对当前官方说明；良好阈值为 LCP 不超过 2.5 秒、INP 不超过 200 毫秒、CLS 不超过 0.1。
- 将这些阈值用于相应指标的第 75 百分位，并按移动与桌面分组；单次工具输出是实验室取值，真实用户 p75 需要线上样本量的分布数据。
- 实验室工具用于复现与回归，真实用户数据用于观察实际分布；TBT 与 INP 分别标注，缺少真实交互测量时说明代理指标与实际交互指标的区别。
- 为导出、训练提交、文件打开等任务增加的端到端指标与 Web Vitals 分列。

## V13 按证据定位性能机制

| 观察到的证据 | 按条件考虑的修复 | 一并复查的代价 |
|---|---|---|
| 非必要模块阻塞首次使用 | 按路由或功能拆包、延迟重资源、优化资源优先级 | 首次打开该功能的等待、失败和重试 |
| 图片字体影响关键呈现 | 优化实际媒体尺寸、格式、加载策略与尺寸预留 | 画质、回退字体、裁切和布局稳定 |
| 同步计算形成长任务 | 按任务性质分块、让出执行机会或迁移 Worker | 消息传输、取消、数据复制与结果身份 |
| 局部输入触发大范围重渲染 | 缩小状态范围、稳定组件边界，再评估缓存 | 过期闭包、数据一致性与代码复杂度 |
| 真实规模下 DOM 或绘制过重 | 比较分页、服务端查询、增量渲染和虚拟化 | 焦点、读屏、查找、打印、选区和滚动恢复 |
| 数据请求重复或响应乱序 | 统一数据来源、适当去重与缓存失效、丢弃旧响应 | 身份隔离、更新后的新鲜度和离线语义 |
| 输出每小段都重排长文本 | 批量更新或稳定内容块，减少不必要重解析 | 中间状态、复制结果、读屏和用户滚动 |
| 媒体或区域尺寸不断改变 | 预留合理空间、稳定异步区及字体回退 | 空白空间、极端内容和小屏 |
| 生命周期后资源未释放 | 清理订阅、计时器、连接、对象 URL 和无界缓存 | 仍被其他实例共享的资源保持可用 |

- 将超过 50 毫秒的主线程任务作为长任务线索；优先级结合真正交互延迟评估，50 毫秒是单个任务的时长线索，不是所有业务操作的总耗时上限。
- 虚拟化、分页与增量渲染在真实规模下的测量证据支持时选用，并在每页实例复查其带来的焦点、读屏、查找、打印、选区与滚动恢复副作用。
- memo、useMemo 与 useCallback 在拿到重复工作证据后引入，并验证缓存收益和失效正确性；计算迁移到 Worker 前核对主线程瓶颈、任务频率、传输成本与取消机制。
- 保留用户需要的内容、语义、日志与功能，性能取舍需要删减时写明理由；动画实现按实际布局与绘制轨迹选择。
- 修复一个机制后复测原问题与相关回归；风险已解决且必要门槛已满足时停止扩展无关测试。

## V14 使用实际可用工具

### 用只读搜索发现候选

**适用条件：** 已有授权访问的本地源码和可用终端时，替换为实际源码目录后运行；把结果当定位线索。

```bash
AUDIT_SOURCE_DIR='src'
rg -n --glob '*.{js,jsx,ts,tsx,vue,svelte,html}' 'aria-live|aria-modal|aria-hidden|tabIndex|tabindex|onKeyDown|composition' "$AUDIT_SOURCE_DIR"
rg -n --glob '*.{js,jsx,ts,tsx,vue,svelte}' 'window[.]|document[.]|Date[.]now|Math[.]random|suppressHydrationWarning|setInterval|addEventListener|createObjectURL' "$AUDIT_SOURCE_DIR"
rg -n --glob '*.{css,scss,less,js,jsx,ts,tsx,vue,svelte}' 'z-index|overflow|position:|100vh|prefers-reduced-motion|outline' "$AUDIT_SOURCE_DIR"
```

- 先确认目录存在并按项目调整扩展名；没有匹配只说明该模式未命中，还需继续核对。
- 阅读命中的定义和调用关系，确认事件、样式和生命周期确实在目标页面使用，再判断上下文；例如存在 aria-hidden 本身需要结合焦点与背景处理才构成缺陷。

### 在已有浏览器能力下执行

1. 打开被审路由并设定真实前置状态，记录实际环境。
2. 通过已记录的工具 API 获取 UI、DOM 或可访问树。
3. 使用能反映角色与名称的定位方式，对重复实例增加上下文，避免操作到错误同名按钮。
4. 执行主动作和相关反向中断，等待实际完成条件。
5. 核对焦点、可见结果、请求与控制台，在能力允许时保存截图或 trace，并把观察回填页面与组件实例记录。

### 在项目已有自动化测试时执行

- 先读取 package 配置、锁文件、测试脚本和 runner 文档，再选择已存在的命令。
- 优先增加能复现确定缺陷的行为测试；样式属性由视觉基准覆盖，不写与实现同义的断言。
- 对异步竞态使用现有 mock 或路由控制能力，以确定的返回顺序复现；对模态检查打开、背景隔离、焦点顺序和关闭后的焦点落点。
- 对输入法保留人工或真机步骤；对响应式使用现有运行器支持的视口和偏好模拟，并写明模拟属性。
- 对无障碍扫描记录工具、规则和页面状态，键盘与读屏路径继续人工核对。
- 仅在命令真正完成并检查输出后报告通过；缺依赖、环境失败、跳过或超时均单列。
